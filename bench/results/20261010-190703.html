Method

  • Fresh state. Before every run the bank is reset and the conversation is new, so a card blocked by one engine is never already blocked for the other.
  • Interleaved. Each query runs on the LLM engine, then on Jev, before the next query, so API latency drift affects both alike.
  • Driven like production. The LLM engine runs through ADK with SSE streaming, as server.py does. Jev runs JevChat.turn(), as the chat page does.
  • Time is wall-clock from sending the message to the last reply token. First token is when reply text starts. A query with no reply is left out of the first-token average.
  • Cost uses Gemini 2.5 Flash paid-tier rates, with token counts from each response's usage metadata. Thinking tokens bill as output. Implicit cache hits bill at the cached rate.
  • Correctness is a hand judgement per query: did the engine take the right action, or give the right answer, without needing another turn it did not need.
  • Single-turn only. A query that needs an OTP ends with the OTP sent, for both engines.
